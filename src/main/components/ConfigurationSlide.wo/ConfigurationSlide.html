Configuration

Composed once, in main(), before the application exists

The sources, each one winning over those above it

  1. Each framework's Properties
  2. The application's Properties
  3. ~/WebObjects.properties, then the machine's
  4. Properties.dev in development, and Properties.<user>
  5. The JVM's -D options, then the application's arguments
  6. Properties set on the running instance
  • Every property knows where it came from: the startup report and the admin console's Configuration page say so
  • Read again when a file changes in development, or a touch file in deployment
  • Frameworks join startup as plugins, found through ServiceLoader

And code can listen

ERXConfigurationManager.onChange(
	"er.example.timeout",
	change -> log.info( "now {}", change.newValue() )
);
